## The fictional study

*Bednet availability and usage in Trans-Nzoia County, Kenya*: a small mixed-methods study, a household survey (~20 synthetic responses) plus key-informant interviews. Fictional researchers: Jane Wanjiru (JW) and David Otieno (DO), Kitale; Anna Lindqvist (AL), KI collaborator. All names, data, and reference numbers are invented. The survey data is generated by a seeded script.

## The "good" folder

```
bednet-survey-transnzoia/
  README            (overview; naming + versioning convention; pointers to material on approved storage)
  DECISIONS         (dated log, 5 entries)
  data/       survey-responses_2024-03-10.csv   (raw, immutable; date = collection date)
  doc/        protocol                          (Doc with version table inside)
              data-dictionary                   (Sheet: variable-level metadata)
              interview-guide                   (Doc with version table inside)
              interview-log                     (Sheet: live tracking, incl. planned + declined rows)
  analysis/   clean-survey-data.R               (defines the cleaning function; every correction in code)
              analysis.R                        (sources it, cleans raw in memory, writes results)
  results/    table1-descriptives.csv           (the only generated file; GEP: analysis outputs go in results)
```

Conventions it models (stated in its README):

- Plain content-based names (GEP), no version or status suffixes. Dates only where the date is content (collection date). Agreed early, applied consistently (KI guidelines, Active data).
- Versioning: 1 a version table inside each governed document per the KI guidelines. A decision log for why things changed.
- No saved intermediates: the cleaning function recreates the analysis-ready data in every run, and results/ holds only generated tables.  (GEP: record all the steps).
- Prose as Google Docs, tables as Sheets (working formats); data as CSV and scripts as plain text (durable formats). 
- Sensitive material (recordings, transcripts, signed consents) on KI-approved storage with regulated access; the folder holds pointers and the tracking log only (Riktlinjer §7).
- Interview log lives in `doc/`, not `data/`: it is a living process document, not immutable collected data. It tracks planned, completed, and declined interviews (auditability: who is missing shapes what the data can say).

## The "poor" folder: planted violations

Folder name on Drive: **`bednet-study`**. The poor folder is a file-for-file mirror of the good one, but with 6 planted violations. Mapping: README (stale), DECISIONS → notes.docx (undated diary), the raw CSV → data.xlsx (silently edited), the two scripts → analysis_final.R (decoy), the generated table → results_tables.docx (hand-made), the interview log kept but stripped of its ids; the data dictionary is simply absent, which is what leaves the red rows and the 99-codes meaningless. Everything else (protocol, interview guide, the log's content) is fine. Numbers do not match, data.xlsx has 19 rows with 2 marked red; the manuscript (dated 2024-03-28) says n = 18, written when one red row was still in; results say n = 17. If looking at the notes.docx, you can find a desicon log to remove two patients - but the workflow with highlighting this in red in the data file leads to several errors downstream.

| # | Planted how | Violates | Reading link |
|---|---|---|---|
| 1 | `data/data.xlsx`: unclear whether raw or already edited (it is edited: one household silently lost, typos silently fixed). No untouched raw version anywhere. | Keep raw data untouched, clearly identified as raw | GEP [Save the raw data](https://carpentries-lab.github.io/good-enough-practices/aio.html#save-the-raw-data); KI Guidelines for research §6 |
| 2 | `analysis/analysis_final.R` looks credible but reads `C:/Users/dotieno/Desktop/data_v2.xlsx` — a path and file that exist nowhere. The script cannot run. | Record every processing step, in runnable code with portable paths | GEP [Record all the steps](https://carpentries-lab.github.io/good-enough-practices/aio.html#record-all-the-steps-used-to-process-data) |
| 3 | Two rows in `data.xlsx` are red with no legend. `doc/notes.docx` holds the only explanation, drowned among per-diem and motorbike entries: "2024-03-20: Marked potential exclusions in red" (no author) and "2024-04-05: Decision by group to exclude the red surveys". The exclusion list exists only as cell colour, which dies on any export. | 4 | `README.docx` is week-1 text: names two files that no longer exist, promises a decision log that was never kept. | README as living overview | GEP [Create an overview](https://carpentries-lab.github.io/good-enough-practices/aio.html#create-an-overview-of-your-project); 5-year test |

Nothing links Grace to her transcript file, and nothing can tell you whether any interviewed person is also a surveyed household (the good log's KII ids are exactly what makes those links possible). The fifth row ("sub-county officer, brief chat at market") is the only trace of that conversation anywhere. | Unique identifiers across files; consent tracking | GEP [Multiple tables, unique identifiers](https://carpentries-lab.github.io/good-enough-practices/aio.html#use-multiple-tables-as-necessary-and-use-a-unique-identifier-for-every-record); [Keele KORSA](https://www.keele.ac.uk/korsa/qualitative/reproducibilityreplication/) (auditability) |
| 6 | The recording of the Grace interview travelled on a USB stick and was lost in transit (notes, 2024-03-17). The transcript reappears three weeks later, retyped from memory (notes, 2024-04-08), as `doc/interview_Grace-M.docx` — participant name in the filename, in the shared folder. The retyped transcript quietly replaces a primary source with recollection. | No sensitive data on portable media; incidents are reported; no personal data in the open; primary data is not reconstructed from memory | KI guidelines, Storage sharing and archiving; Riktlinjer §7 |

Deliberately fine, to keep the folder credible: the protocol and interview guide are decent documents matching the study as conducted (their only quiet gap: no version tables), the interview log is genuinely maintained, and the folder skeleton itself is correct. The teaching point is that structure alone does not make a project reproducible.

## Expected team findings and facilitation

Will likely find 4 quickly (README vs actual contents). 1, 2, and 6 require reading files closely; 3 and 5 require cross-referencing several files, and the full n = 19/18/17 reconstruction is a stretch goal — praise any team that gets there. Prompts:

- If a team posts only surface findings: "Could you redo their analysis five years from now? What exactly stops you? Which rubric question does that hit?"
- If a team never opens the rubric: "Try Decision traceability or Orientability on both folders — where does each answer live?"
- Discussion prompt on the good folder: "Why is the interview log in `doc/` and not `data/`?" (living document vs immutable data; Separation of concerns).
- Discussion prompt on versioning: "This team versions through version tables + the decision log. What else could they have chosen, and when would that be better?" Talking points: filename versioning with dated copies (KI name parts), git if already used.
