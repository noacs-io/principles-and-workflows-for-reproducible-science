# Session → Swedish Research Council DMP map

**Course assignment:** (1) Data management plan using the Swedish Research Council template, and (2) data collection protocol.  
**These two days focus on (1).** Use your own PhD project.

Template file in this repo: [`Swedish_Research_Council_Template__v5.docx`](../Swedish_Research_Council_Template__v5.docx) (same template as in DMPonline).

## How to use this handout

After each major activity:

1. Update your **project package** (folder + README + decision log, etc.).
2. Open the SRC template (Word or DMPonline).
3. Paste or adapt today’s text into the matching section below. Mark it as *draft*.

## Mapping

| When you produce… | Paste into SRC section… | Tip |
|-------------------|-------------------------|-----|
| Project title, your name, dates, short aim (README) | **General information** | Keep versions dated. |
| How you collect/create/reuse data; why not reuse (if relevant); how you record provenance | **Description of data** — how collected/created/reused | Be concrete about methods/tools. |
| Data types, formats (e.g. `.csv`, `.xlsx`, audio), rough volume, folder layout, naming rules | **Description of data** — types, formats, volume | Prefer open formats when you can. |
| README, decision log, data dictionary, folder conventions, versioning | **Documentation and data quality** — documentation/metadata | This is the strongest fit with these sessions. |
| Checks you will use for documentation/data handling quality | **Documentation and data quality** — quality safeguards | Collection-field QC belongs mainly in the **protocol**. |
| Where data live during the project; backup; raw vs derived folders | **Storage and backup** | Use KI-approved storage — not USB/personal Drive. |
| Who can access what; what must not go in public GitHub or AI tools | **Storage and backup** — security / access | Never put personal/patient data in prompts. |
| Consent, ethics approval location, sharing limits, IP | **Legal and ethical aspects** | Confirm details with KI support functions. |
| What could be shared later; metadata; long-term readability (5-year test) | **Accessibility and long-term storage** | “As open as possible, as closed as necessary.” |
| Who owns the folder, docs, and DMP updates; time/cost for documentation | **Responsibility and resources** | Name people where you can. |

## What these sessions do *not* replace

The **data collection protocol** (timelines, staffing, field logistics, detailed collection QC) is the other assignment component. Here we only note where instruments/versions live and how documentation supports quality — write the full protocol elsewhere in the course.
