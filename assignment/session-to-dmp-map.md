# Session → Swedish Research Council DMP map

**Course assignment:** (1) Data management plan using the Swedish Research Council template, and (2) data collection protocol.  
**These two days focus on (1).** Use your own PhD project.

Template file in this repo: [`Swedish_Research_Council_Template__v5.docx`](../Swedish_Research_Council_Template__v5.docx) (same template as in DMPonline).

## How to use this handout

After each major activity:

1. Update your **project package** (folder + README + decision log, etc.).
2. Open the SRC template (Word or DMPonline).
3. Paste or adapt today’s text under the **exact template question** below. Mark it as *draft*.

## Mapping (template questions verbatim)

| When you produce… | Paste under this SRC template question… | Tip |
|-------------------|-------------------------------------------|-----|
| Project title, your name, dates, short aim (README) | **General Information** — Project Title / Project Leader / Date / Version | Keep versions dated. |
| How you collect/create/reuse data; why not reuse (if relevant); how you record provenance | *How will data be collected, created or reused?* | Be concrete about methods/tools. |
| Data types, formats (e.g. `.csv`, `.xlsx`, audio), rough volume, folder layout, naming rules | *What types of data will be created and/or collected, in terms of data format and amount/volume of data?* | Prefer open formats when you can; mention folder organisation in the same answer. |
| README, decision log, data dictionary, folder conventions, versioning, metadata approach | *How will the material be documented and described, with associated metadata relating to structure, standards and format for descriptions of the content, collection method, etc.?* | Strongest fit with these sessions. |
| Checks for documentation/data-handling quality (validation, peer review of docs, etc.) | *How will data quality be safeguarded and documented (for example repeated measurements, validation of data input, etc.)?* | Field/collection QC belongs mainly in the **protocol**. |
| Where data live during the project; backup; raw vs derived folders | *How is storage and backup of data and metadata safeguarded during the research process?* | Use KI-approved storage — not USB/personal Drive. |
| Who can access what; what must not go in public GitHub or AI tools | *How is data security and controlled access to data safeguarded, in relation to the handling of sensitive data and personal data, for example?* | Never put personal/patient data in prompts. |
| Confidentiality, personal data, IP, access rules | *How is data handling according to legal requirements safeguarded, e.g. in terms of handling of personal data, confidentiality and intellectual property rights?* | Confirm details with KI support functions. |
| Consent, ethics review, ethical storage/sharing constraints | *How is correct data handling according to ethical aspects safeguarded?* | Link to where ethics documents live. |
| What could be shared later; metadata; embargoes; long-term readability (5-year test) | *How, when and where will research data or information about data (metadata) be made accessible? Are there any conditions, embargoes and limitations on the access to and reuse of data to be considered?* | “As open as possible, as closed as necessary.” |
| Who archives what; what is kept long term | *In what way is long-term storage safeguarded, and by whom? How will the selection of data for long-term storage be made?* | Align with KI archiving rules. |
| Software needed to open/analyse files later | *Will specific systems, software, source code or other types of services be necessary in order to understand, partake of or use/analyse data in the long term?* | Brief is enough at this stage. |
| DOI / persistent identifiers (if known) | *How will the use of unique and persistent identifiers, such as a Digital Object Identifier (DOI), be safeguarded?* | Often provided by a repository later. |
| Who owns the folder, docs, and DMP updates during and after the project | *Who is responsible for data management and (possibly) supports the work with this while the research project is in progress? Who is responsible for data management, ongoing management and long-term storage after the research project has ended?* | Name people where you can. |
| Time/cost for documentation, storage, preparing data for sharing | *What resources (costs, labour input or other) will be required for data management (including storage, back-up, provision of access and processing for long-term storage)? What resources will be needed to ensure that data fulfil the FAIR principles?* | Rough estimates are fine for a draft. |

## What these sessions do *not* replace

The **data collection protocol** (timelines, staffing, field logistics, detailed collection QC) is the other assignment component. Here we only note where instruments/versions live and how documentation supports quality — write the full protocol elsewhere in the course.
